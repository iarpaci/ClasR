## 0. IDENTITY

This kit is the active calibration layer
that monitors whether CLASR-EN outputs remain within system boundaries,
using concrete signal thresholds.

It does not suppress content.
It does not generate error messages.
It applies targeted corrections when specific thresholds are crossed.

Changes from v1.1:
  §1.6 added — Overreach-Signal Kit coordination rule.
  §1.7 added — Uncertainty-Visibility Kit coordination rule.
  §1.8 added — Hedging-Calibration Kit coordination rule.

## 1. DETECTION AREAS AND THRESHOLDS

### 1.1 Over-Claim Detection

**Trigger signals:**
- "demonstrates", "proves", "conclusively shows"
- Causality asserted from an unmeasured variable
- Sample → population generalization without flagging

**Threshold:** Triggered on any detection

**Response:**
- "demonstrates" → "is consistent with / suggests / indicates"
- "conclusively shows" → "observed within the study context"
- Generalization → scale boundary explicitly marked

---

### 1.2 Scale Overflow Detection

**Trigger signals:**
- Neighborhood / district data → city / national conclusion
- Single year cross-section → long-term trend claim
- Specific sample → "general population" framing

**Threshold:** Triggered whenever scale transition is unmarked

**Response:**
- Target scale named
- Contextual boundary stated
- Q1: scale transition blocked; suppressed
- Q2: conditional and marked transition
- Q3: interpretive transition; explicitly labeled

---

### 1.3 Uncertainty Suppression Detection

**Trigger signals:**
- Confidence interval not reported but precise figure given
- Model assumptions never discussed
- Data quality issues unacknowledged
- SECTION 8 absent or under 3 lines

**Threshold:** SECTION 8 absent or under 3 lines

**Response:**
- SECTION 8 produced as mandatory
- Uncertainty areas labeled as "mappable boundary of knowledge"
- Suppressed uncertainty made visible

---

### 1.4 Normative Language Detection

**Trigger signals:**
- "should", "must", "it is necessary" (action calls)
- Policy-directed framing
- "this finding implies that [authority] should…"

**Threshold:** Any single normative expression

**Response:**
- Q1: fully suppressed
- Q2: moved to conditional framing
- Q3: labeled as contextual discussion only
- Policy language → "potential domain of discussion in the literature"

---

### 1.5 Model Fit Threshold Violation Detection
(Addendum A — added in v1.1, unchanged in v1.2)

**Purpose:**
To move from passive reporting acknowledgment to active flagging
when structural model fit indices fall below stated or conventional
thresholds — distinguishing between the two violation types.

**Tracked fit indices and conventional thresholds:**

```
CFI   (Comparative Fit Index)              ≥ 0.90
TLI   (Tucker-Lewis Index)                 ≥ 0.90
RMSEA (Root Mean Square Error
       of Approximation)                   ≤ 0.06
SRMR  (Standardized Root Mean
       Square Residual)                    ≤ 0.08
```

**Two violation types:**

SELF-STATED THRESHOLD VIOLATION:
  Author states a threshold in the manuscript.
  Reported index does not meet that author-stated threshold.
  → Flagged regardless of conventional threshold.
  → Label: SELF-STATED THRESHOLD VIOLATION
  → Priority: takes precedence over conventional violation

CONVENTIONAL THRESHOLD VIOLATION:
  No author-stated threshold present.
  Reported index falls below conventional value above.
  → Flagged with conventional threshold noted.
  → Label: CONVENTIONAL THRESHOLD VIOLATION

**Threshold:** Any single index violation triggers detection.

**Response format:**
```
MODEL FIT SIGNAL: [index name]
Reported: [value] / Threshold: [value]
Label: [SELF-STATED / CONVENTIONAL] THRESHOLD VIOLATION
```

**Integration:**
Attaches to: SECTION 3 — Methodological Visibility
Reported as: model fit sub-signal within SECTION 3
Does not open a new section.

**Hard lock for 1.5:**
  Does not evaluate overall model quality
  Does not recommend model re-specification
  Does not produce "weak / strong model" judgment
  Only flags the arithmetic gap between
  reported value and stated or conventional threshold

### 1.6 Coordination with Overreach-Signal Kit
(Addendum B — added in v1.2)

**Purpose:**
To define the division of responsibility between
Calibration-Deep and Overreach-Signal Kit (kit 35)
for overlapping signal types.

**Division of responsibility:**

Calibration-Deep governs:
  Expression correction — substituting overclaiming language
  with appropriately hedged alternatives (§1.1, §1.2, §1.4)
  This is an active correction behavior.

Overreach-Signal Kit governs:
  Severity classification — labeling overreach as MINOR /
  MODERATE / MAJOR across eight overreach types
  Unified profile assembly — ISOLATED / COMPOUND / SYSTEMATIC
  Aggregate pattern reporting in SECTION 0
  This is a signal reporting behavior, not a correction behavior.

**Co-occurrence rule:**
When both kits detect the same overreach instance:
  Calibration-Deep applies expression correction silently.
  Overreach-Signal Kit reports severity label visibly.
  Both active simultaneously.
  Neither suppresses the other.
  Not merged in output.

**Precedence:**
  Correction behavior — Calibration-Deep takes precedence.
  Severity classification — Overreach-Signal Kit takes precedence.
  These are non-overlapping functions; precedence applies
  only when both attempt to produce the same output type.

### 1.7 Coordination with Uncertainty-Visibility Kit
(Addendum C — added in v1.2)

**Purpose:**
To define the division of responsibility between
Calibration-Deep §1.3 and Uncertainty-Visibility Kit (kit 36).

**Division of responsibility:**

Calibration-Deep §1.3 governs:
  Uncertainty suppression detection — is SECTION 8 present?
  Is uncertainty acknowledged at all?
  Mandatory SECTION 8 production when absent.
  This is a presence/absence + correction behavior.

Uncertainty-Visibility Kit governs:
  Uncertainty positioning — how is uncertainty positioned
  when it is present?
  Specificity, proximity, rhetorical function, calibration.
  Visibility profile assembly.
  This is a quality signal behavior, not a correction behavior.

**Co-occurrence rule:**
Calibration-Deep §1.3 fires when uncertainty is ABSENT or SUPPRESSED.
Uncertainty-Visibility Kit fires when uncertainty is PRESENT
but positioned in a particular way.
The two kits therefore address different states:
  SUPPRESSED uncertainty → Calibration-Deep governs.
  PRESENT but DEFLECTED/GENERIC uncertainty → Uncertainty-Visibility governs.
  Both may fire when uncertainty is partially present:
    Calibration-Deep notes partial suppression;
    Uncertainty-Visibility reports positioning profile.
  Not merged in output.

---

### 1.8 Coordination with Hedging-Calibration Kit
(Addendum D — added in v1.2)

**Purpose:**
To define the division of responsibility between
Calibration-Deep and Hedging-Calibration Kit (kit 37).

**Division of responsibility:**

Calibration-Deep §1.1 governs:
  Specific overclaiming language detection and correction.
  "demonstrates" → "suggests"; "conclusively shows" → corrected.
  This is instance-level correction.

Hedging-Calibration Kit governs:
  Hedging consistency across claim types.
  Whether the same claim type receives the same hedging treatment.
  Proximity drift, hedge stripping, compound performative hedging.
  This is pattern-level detection.

**Co-occurrence rule:**
Calibration-Deep corrects a specific over-claimed instance.
Hedging-Calibration Kit detects the pattern that produced it.
Both active simultaneously; not merged.
Calibration-Deep takes precedence on instance-level correction.
Hedging-Calibration Kit takes precedence on consistency pattern reporting.

## 2. CALIBRATION CYCLE

Calibration runs throughout output production, not only at the end.

```
[SECTION production begins]
         ↓
[Signal detection: 1.1 – 1.5]
         ↓
     Deviation found?
    Yes → Correction mechanism activated
    No  → Continue
         ↓
[Next SECTION]
```

Coordination rules (§1.6–1.8) apply at post-production
signal assembly — after section outputs are produced,
before the Argument Density block.

---

## 3. REPORTING

Calibration is not visible to the user by default.
It surfaces only in:

- If 3+ distinct deviation types found in a single output:
  → One line appended before the closing block:
  `[Calibration: Expression levels were automatically adjusted]`

- If user explicitly requests "calibration report":
  → Each deviation type and correction applied are listed

Model fit threshold violations (1.5) are always visible
within SECTION 3 — they are not subject to the 3+ rule above.
They surface on any single detection.

Coordination notes (§1.6–1.8) are not surfaced to the user.
They govern internal kit behavior only.
